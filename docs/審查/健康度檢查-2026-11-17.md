# ModernMenuManager 程式碼健康度檢查（2026-11-17）

範圍：reberu6/ModernMenuManager 預設分支（ef96f31，v0.1.2），全部 8 個 .cs 檔 + build.yml，約 900 行。只看程式碼，沒有改、沒有推送。
整體：程式小、結構清楚，登錄檔寫入範圍正確（只動 Shell Extensions\Blocked），提權輔助模式有驗證 GUID。沒有會損壞系統的問題。下面依嚴重度排序。

## A. 會卡住或當掉（優先修）

1. **掃描可能永遠卡在「掃描中」** — `MenuScanner.cs:126-146`
   讀 PowerShell 輸出的 `ReadLine()` 沒有逾時，`WaitForExit(30000)` 要等讀完才執行，等於沒作用。PowerShell 一卡住（防毒攔、AppX 服務慢），整個程式按鈕全灰、只能強制關閉，PowerShell 行程也不會被結束。
   修法：用 `BeginOutputReadLine` 或另開工作讀取，整體逾時（例如 30 秒）後 `Kill()` PowerShell，並記 log，繼續用登錄檔結果。

2. **沒有全域例外處理，部分操作會跳 .NET 當機視窗** — `Program.cs`、`MainForm.cs:213`
   例：「複製 CLSID」時剪貼簿被別的程式占用，`Clipboard.SetText` 會丟例外直接跳錯誤視窗；所有 async 按鈕的意外例外也一樣，而且不會寫進記錄檔。
   修法：`Application.ThreadException` + `AppDomain.UnhandledException` 寫 log 並顯示友善訊息；`CopyClsid` 包 try/catch。

3. **重新啟動檔案總管的副作用** — `MainForm.cs:224-242`
   - 會殺掉「所有」名為 explorer.exe 的行程，包括 Sandboxie 沙箱裡的 explorer。
   - UI 執行緒上 `WaitForExit(5000)` × 行程數 + `Sleep(2000)`，視窗會短暫「沒有回應」。
   - 2 秒後若 Windows 還沒自動重啟殼層，程式自己啟動一個；Windows 隨後也重啟時，可能多開一個檔案總管資料夾視窗。
   修法：只結束殼層那一個（`GetShellWindow` → PID），放到背景執行，輪詢最多約 10 秒確認殼層回來才自己啟動。

## B. 安全

4. **用不含路徑的檔名啟動系統程式（DLL/EXE 搶占）** — `MenuScanner.cs:116`、`MainForm.cs:235,247`
   `powershell.exe`、`explorer.exe`、`notepad.exe` 都只給檔名。Windows 會先在「本程式所在資料夾」找，所以若 exe 放在下載資料夾，而那裡剛好有同名惡意檔，就會被執行（之後再提權時風險更大）。
   修法：改用完整路徑，例如 `Path.Combine(Environment.SystemDirectory, @"WindowsPowerShell\v1.0\powershell.exe")`、`%WINDIR%\explorer.exe`、`System32\notepad.exe`。
   實際風險：中低（要先有惡意檔放在同資料夾），但修起來很便宜。

5. **CI 每次推送到任何分支都發公開正式版 Release** — `.github/workflows/build.yml`
   測試分支的推送也會產生 `v0.1.N` 正式版（非 prerelease），別人或自己容易下載到未測版本；這也是「推送前要先問」的原因。另外 actions 只用標籤（@v4）沒有鎖 SHA，權限 `contents: write` 給整個 workflow。
   修法：只有預設分支（或打 tag）才發 Release，其他分支只上傳 artifact；權限只給發布那一步。

## C. 小錯誤 / 使用體驗

6. **「隱藏給所有使用者」失敗或取消時沒有任何提示** — `MainForm.cs:202`；提權輔助失敗時回傳 1 但不記原因（`BlockList.cs:116-119`）。
7. **等 UAC 時整個視窗凍結** — `BlockList.cs:81` 在 UI 執行緒 `WaitForExit()`，UAC 視窗放著不按，主視窗就「沒有回應」。改成 `await Task.Run(...)`。
8. **每次掃描都會啟動所有 App 的選單 COM 伺服器** — `MenuScanner.cs:308-336`
   為了取標題，會實際啟動每個 App 的選單元件（可能拉起 OneDrive、百度網盤等的背景行程）；超過 8 秒的會被丟著不管，物件和行程可能留著；`CoInitializeEx` 沒有配對 `CoUninitialize`。功能上可接受，但建議：快取上次標題、已隱藏項目不必每次探測、逾時的記到 log。
9. **勾選切換時一直 new Font 沒釋放** — `MainForm.cs:152`。每點一次多一個 GDI 字型物件（等 GC 才回收）。改用兩個預先建立的 Font 欄位。量不大，但你之前碰過 GDI 洩漏問題，順手修。
10. **套用到一半寫入失敗** — `MainForm.cs:171-181`：會顯示錯誤，但不說哪些已套用、哪些沒有；之後重新整理會反映真實狀態，所以不會錯亂，只是訊息不清楚。

11. **沒有任何測試**。可先把純邏輯抽出來測：`LooksLikeText`、`Resolve` 的候選字串、`MenuEntry.Title`（& 處理）、`DescribeItemType`、`RunMachineCommand` 的參數解析，在 CI 加一個 `dotnet test`。

## 確認過沒問題的地方

- 只寫 HKCU / HKLM 的 `Shell Extensions\Blocked`，恢復時只刪自己比對到的 GUID 值，不會誤刪其他登錄項。
- 提權模式只接受 block/unblock 和合法 GUID，其他參數忽略。
- COM 探測用 `CLSCTX_LOCAL_SERVER`（在別的行程跑），壞掉的擴充不會讓本程式當掉。
- Manifest XML 解析：.NET 4.8 預設不載入外部實體，安全。
